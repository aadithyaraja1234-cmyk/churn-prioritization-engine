# Live-demo dataset library — v2 (naming-convention stress batch)

> **SAMPLE/DEMO DATA — not real company data.** Every company name,
> customer/member/client ID, and value in this folder is synthetic,
> generated by
> [`scripts/generate_live_demo_v2_batch.py`](../../scripts/generate_live_demo_v2_batch.py)
> from a fixed random seed. None of these five companies exist. Do not
> treat any of this as real customer, financial, or business data.

Distinct from **`data/live_demo/`** (the first 6-company live-demo batch -
ordinary snake_case/space-separated column names throughout) and
**`data/test_onboarding_samples/`** (deliberately messy - thin data,
data-quality rot, a malicious upload). This batch reuses the first live-demo
batch's design (every company gets the full mappable-role set, genuine
churn structure, no injected data-quality issues, offline pre-checked) but
exists for one additional purpose: **deliberately, aggressively varying
column-NAMING CONVENTION** to stress-test the tenant_config column-name
generalization work (`business_impact.py`/`prioritize.py`/`backtest.py`/
`scenario.py`/`recommend.py`/`timeline.py` - see
`docs/ADDING_A_TENANT.md`'s recurring-lessons section: this exact
hardcoded-column-name bug pattern has recurred at least three times for
real - Meridian's action-queue/alerts, Aurora's business-impact, and
`recommend.py` again).

Nothing in this folder has been registered as a company, uploaded, or
trained by generating it - **generate-and-save only**, same as
`data/live_demo/`. Regenerate all five deterministically with:

```
python scripts/generate_live_demo_v2_batch.py
```

## Column-to-role mapping (for the live mapping-step demo)

Same convention as `data/live_demo/README.md`: there is no "segment" role
in `src/onboarding/schema_fields.py`'s `VALID_ROLES` -
`segment_feature_column` is auto-derived by `survival.py` from whichever
categorical covariate the fitted Cox model's own hazard ratios deviate
furthest from 1.0, so during real onboarding the tier/plan/care-level
column below is mapped to plain `feature`, same as every other one. Every
tier/plan/care-level label was chosen so its **alphabetical order already
matches its intended risk order** (highest-risk name sorts first) - the
same THE-SEGMENT-COLUMN-DOMINANCE-TRICK convention `data/live_demo/`'s
companies use (see that README's own explanation) - confirmed below by
each file's real, fitted hazard-ratio coefficients.

## Pre-check #1: column-mapping auto-suggestion (offline, throwaway - not a real upload)

Ran every file's real column names through the actual
`src.onboarding.schema_fields.suggest_mapping()` (+
`suggest_duration_leakage_column()`) - the same name-similarity suggestion
logic the real mapping-step UI calls - and compared each suggestion
against the ground-truth intended role above. **This is the whole point of
this batch**: knowing in advance which columns will show the "please
confirm" low-confidence path during a live demo, rather than being
surprised by it live.

| File | Auto-suggested correctly | Notably wrong (not just low-confidence "ignore") |
|---|---:|---|
| `vantage-legal-services.csv` | 1/15 | `Case Load Estimate` → suggested **clv** (matched "CLTV", conf 0.74) |
| `ridgeline-outdoor-gear-club.csv` | 2/14 | none - all misses landed on "ignore" |
| `beacon-home-security.csv` | 3/14 | `estimatedValue` → suggested **feature** (matched "EstimatedSalary", conf 0.76), not clv |
| `thornfield-pet-insurance.csv` | 2/14 | none - all misses landed on "ignore" |
| `meadowbrook-senior-living.csv` | 1/14 | none - all misses landed on "ignore" |

Every file's `customer_id`/`revenue` columns (and Ridgeline/Beacon's
`target`) that happen to closely resemble a known alias (`cust_id`≈
`customer_id`, `customerId`≈`customerID`, `churn`≈`Churn`,
`monthlyFee`≈`MonthlyCharges`) auto-suggest correctly, exactly as
intended - name-similarity matching genuinely works when the name is
close. Everything else - and especially Vantage's fully-spelled-out
"Monthly Retainer Fee"/"Left Firm"/"Client Reference Number", Thornfield's
all-caps `PREMIUM` and ambiguous `Status`, and Meadowbrook's
punctuation-laden names - lands on "ignore" (or, twice, an actively wrong
role) and needs a human to manually pick the correct role from the
dropdown live. That's the intended demo moment, not a bug: it's real
evidence of where the auto-suggestion tool's name-similarity approach
runs out, which is exactly what "designed to stress-test the column-name
generalization work" means in practice.

## What this batch is for (and isn't)

This is an **offline pre-check only** - generate, check mapping
suggestions, check sufficiency, check real training/gating - not a
registration or training run. Nothing here has a company row, an uploaded
file under `data/tenant_uploads/`, or a `models/<tenant>/` directory. The
actual register → upload → map (live, expect several "please confirm"
corrections per file - see Pre-check #1 above) → validate → train flow
happens live, by a person, choosing whichever of these five best fits the
moment - same as `data/live_demo/`'s own workflow.
